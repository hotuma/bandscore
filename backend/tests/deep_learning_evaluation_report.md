# ディープラーニング BPM 検出ライブラリ実用性評価報告

## 検証日
2026-04-12

## 検証環境
- OS: Windows 11 Pro
- Python: 3.13 / 3.12
- CPU: 現状不明

## 検証対象ライブラリ

### 1. madmom
**インストール状態**: ❌ 失敗
- **エラー内容**: `ModuleNotFoundError: No module named 'Cython'`
- **原因**: Python 3.13 に対応していない
- **対応状況**: Cython インストール後もビルドエラー
- **実用性**: 現状では使用不可

**特徴**:
- CNN + LSTM ベースの深層学習モデル
- 高精度なビート/ダウンビート検出
- 学習済みモデル提供

**推定性能** (文献より):
- BPM 検出精度: >95% (Ballroom データセット)
- リアルタイム処理: 10-20x

### 2. BeatNet
**インストール状態**: ❌ 失敗
- **エラー内容**: `ModuleNotFoundError: No module named 'madmom'`
- **原因**: madmom に依存している
- **対応状況**: 依存関係の問題で動作せず
- **実用性**: 現状では使用不可

**特徴**:
- CNN + Temporal Convolutional Network (TCN) ベース
- バーストベースのビートトラッキング
- 学習済みモデル提供

**推定性能** (文献より):
- BPM 検出精度: >93% (Ballroom データセット)
- リアルタイム処理: 15-30x

### 3. librosa (現行実装)
**インストール状態**: ✅ 成功
- **バージョン**: 0.11.0
- **対応状況**: 動作中

**測定結果** (ガソリン0812.m4a, 203.8秒):
- **処理時間**: 4.72 秒
- **メモリ増加**: 197.7 MB
- **処理速度**: 43.16 xリアルタイム
- **検出BPM**: 89-234 BPM (不安定)
- **期待BPM**: 162 BPM

**精度評価**:
- 162 BPM の検出: ❌ 失敗
- パラメータ調整: 🔵 検証中
- 一貫性: 🔴 低い

## 分析と評価

### 1. 導入容易性

| ライブラリ | インストール | 依存関係 | スコア |
|-----------|-------------|----------|--------|
| madmom    | ❌ 失敗    | Cython, numpy | 0/10 |
| BeatNet   | ❌ 失敗    | madmom, torch | 0/10 |
| librosa   | ✅ 成功    | 標準的な依存 | 10/10 |

**結論**:
- 現行の Python 3.13 環境では madmom 系ライブラリは導入困難
- Python 3.12 以下へのダウングレードが必要
- 依存関係の管理が複雑

### 2. 処理性能

| ライブラリ | 処理速度 | メモリ消費 | スコア |
|-----------|----------|-----------|--------|
| madmom    | 10-20x   | 中程度     | 8/10* |
| BeatNet   | 15-30x   | 中程度     | 9/10* |
| librosa   | 43x      | ~200 MB   | 10/10 |

*: 文献値による推定

**結論**:
- librosa は処理速度が優れている
- メモリ消費は 200 MB 程度で許容範囲
- クラウド環境での実用性は十分

### 3. 検出精度

| ライブラリ | BPM 精度 | オクターブ誤検出 | スコア |
|-----------|----------|----------------|--------|
| madmom    | >95%     | 低い           | 9/10* |
| BeatNet   | >93%     | 低い           | 8/10* |
| librosa   | 不定     | 高い           | 3/10 |

*: 文献値による推定

**結論**:
- librosa は音楽によって精度が大きく変動
- オクターブ誤検出（倍速/半速）が頻発
- パラメータ調整が必要で汎用性が低い

## 実用性評価

### クラウド環境での考慮

**Render (Free Tier)**:
- メモリ制限: 512 MB
- CPU: 共有
- 制限: `MAX_ANALYSIS_SEC` = 120秒

**推論**:
- librosa の 200 MB メモリ消費は許容範囲内
- 43x の処理速度は十分な性能
- ただし、精度の問題が実用的な用途を制限

### 推奨アプローチ

#### オプション A: librosa ベースの改善 (推奨)
**メリット**:
- 導入容易、依存関係がシンプル
- 処理速度が速い
- メモリ消費が低い

**課題**:
- 精度が不安定
- パラメータ調整が必要
- 音楽ジャンルによって性能が変動

**改善策**:
- 複数の BPM 検出手法の組み合わせ
- ユーザーによる BPM 手動調整機能
- 音楽ジャンル別の最適化

#### オプション B: Python 3.12 環境への切り替え
**メリット**:
- madmom/BeatNet が使用可能
- 高精度な BPM 検出

**課題**:
- 環境切り替えの手間
- 依存関係の管理が複雑
- メモリ消費が増加する可能性

**注意点**:
- Python 3.13 への将来のアップグレードが困難

#### オプション C: ハイブリッドアプローチ
**アプローチ**:
1. 第1段階: librosa で初期 BPM 推定 (高速)
2. 第2段階: 検出された BPM 周辺で詳細探索
3. 第3段階: オクターブ検証と補正

**メリット**:
- librosa の速度を維持
- 精度を向上
- 柔軟な調整が可能

**実装の優先度**: 高

## 結論

### 現状での推奨
**librosa ベースの改善 + ユーザー調整機能**

**理由**:
1. 環境互換性の問題がない
2. 処理速度が十分
3. ユーザーによる手動調整で精度問題を補完

### 将来の検討
**madmom/BeatNet の導入検討タイミング**:
1. Python 3.12 以下の環境要件がある場合
2. 高精度な BPM 検出が必須な場合
3. 専用サーバー環境で依存関係の管理が可能な場合

### 次のステップ
1. **ハイブリッド BPM 検出の実装**
   - 第1段階: librosa による初期推定
   - 第2段階: 候補 BPM の詳細スコアリング
   - 第3段階: バス帯域でのオクターブ検証

2. **ユーザー調整機能の実装**
   - BPM 手動調整 UI
   - プレビュー再生による確認

3. **複数手法の組み合わせ**
   - 自己相関法
   - スペクトル差分法
   - バス帯域法
